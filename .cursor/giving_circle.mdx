# Giving Circle

Architecture and non-obvious gotchas for this app. File names, CSS, Puck field shapes, and current helpers belong in the code. Style, TypeScript, Rails, i18n, and CSS conventions live in `.cursor/rules/` and are not repeated here.

## Domain

- Circle-specific config lives in `circles.settings` jsonb (`Circle::Settings`). Site-wide config belongs in `rails-settings-cached` when that is added.
- Presentations have a slide deck (room display) and optional Interactions (member input). The public page `/:circle_slug/p/:presentation_slug` is display-only. Member input is `.../interact` (signed-in membership required).
- At most one interaction per presentation may have `accepting_responses: true`. Open/close is only from Active Presentation Controls, not Interaction Show.
- Member screens are Puck layouts in `member_ui` jsonb. `Interactions::MemberUiCompiler` compiles placed inputs into interaction `config` on save. Slide and member editors share one Visual Editor shell and differ by Puck config.
- Interaction org fields always use `presentation.orgs`, never theme orgs. Live `finalist_org_ids` come from any interaction that outputs `org_vote_totals` (top N from `presentation.settings.finalist_count`); missing or empty responses means all presentation orgs. Do not shrink `presentations_orgs` when finalists change.
- Responses are not unique on `(interaction, membership)`: some types (pledges) create many rows. Per-member interaction budgets live on `presentation_interaction_memberships.member_attributes`, not `presentations_memberships.funds` (presentation-scoped money only).
- Models persist. Interaction runtime lives in `app/services/interactions/` as `Interactions::*`.
- Live slide Elements read Redis `presentation_values`, not raw `interaction_responses`. Postgres remains the source of truth for response rows. Cache refresh is scheduled only for `active` presentations; ActionCable broadcasts only when the snapshot changes. Do not `broadcast_to` from models or fire cable from controllers.
- One `PresentationDataProvider` owns Inertia presentation props and the single values-channel subscription. Mount it at the presentation surface. Elements must not open their own subscriptions or nest another provider.
- Money on the wire is `@/types` `Money`. Convert cents only through `@/lib/money`. Never divide or multiply by 100 in UI.
- Circle outbound email/SMS uses `Integration` (`medium` + `provider` + encrypted credentials). There is no Circle Smtp table. Vendor presets live in `Messaging::ProviderCatalog`; a new vendor is a catalog preset plus an adapter. `MessageTemplate` copies into `Presentation::Message`. Recipients are resolved from presentation memberships at send time, not stored on the message. Setup is under the presentation menu; Active Presentation messaging is send-only. Template variables are `#path` tokens expanded at send.

## Persistence and routes

- Serialize presentations through the `slides` association, not the JSONB `slides` column.
- Slide editor URLs use FriendlyId slugs. Numeric indices 404.
- Destroying a slide nullifies `active_slide_id` and `SlideParent` rows in model callbacks so FK order stays valid.
- Thumbnails are captured in the editor at save (client `html-to-image`) and attached on `Slide`. Do not screenshot from a job.
- Historical slugs: `FriendlyIdHistory`; old slugs 301 to current.
- Nested theme/presentation routes are declared twice (outer `param: :theme_slug` / `:presentation_slug` for CRUD, inner `param: :slug` for nested) so Rails does not emit `:theme_theme_slug`-style names.
- Rails reserves `actions` as a route segment; this app does not use that name.
- Controller `@route` comments come from `rails annotate:routes`. Do not hand-edit them.
- The `urlParams.ts` generator must `reload_routes!` first; lazy route loading otherwise writes an empty file.
- During active development, edit the original create/alter migration instead of stacking throwaway migrations.

## Visual Editor

- Layout is flex/grid first. Puck wraps children in a DropZone `div`. Live/preview that wrapper is `display: contents` so host flex/grid applies to the blocks; the editor DropZone stays a real box so it can receive drops.
- Components that must honor flex/grid item sizing set Puck `inline: true` and put `puck.dragRef` on the actual root. Without that, grow/stretch apply to Puck's wrapper. Layout boxes use Fill/Auto item sizing; chrome widgets use an explicit size.
- `#path` tokens are interpolated by `useResolvedTags`. Iterate (`presentation.org`) lives on Container and Grid. Editor shows one template; live maps once per item.
- Server JSON is the source of truth. `localStorage` is a recovery draft only. Save writes the API. Unsaved navigation is `NavigationInterrupt`. Member UI save is XHR, not an Inertia visit: a visit would trip the leave-page guard (GET / history back only).
- Puck `resolveData` rewrites the document on mount. Dirty-check against a clone of that resolved snapshot, not the live Puck object, or Save stays disabled.
- Starter `ComponentData` must include stable `props.id` values or Puck can loop `onChange` and exhaust memory.
- During active development, slide JSON is throwaway: when a field format changes, drop the old keys. Do not keep dual stored shapes.
- Custom fonts are circle-scoped attachments. Slide JSON stores `{ family, url }`; `family` alone is a CSS generic.
- Live `presentation.orgs` falls back to `theme.orgs` when the presentation has none; preview uses mock circle orgs. An empty array is not missing data. New presentations copy theme orgs on create. Do not preload `Theme#orgs` on public loads.
- Puck components split Display (live) vs Editor (canvas). Stored props live on the entry module, not the config. Config copy calls `i18n.t` inline. Field factories must not take a `t` parameter.
- Property sidebar is a dense design-tool layout: grouped panels per concern, one control per stored value. Do not ship a stack of default Puck/Mantine widgets for style props.
- `legacySideBarPlugin` mounts the same fields twice (one copy is 0-width). Segmented controls need a unique radio `name` per instance or label clicks hit the hidden copy.
- Modules under `VisualEditor/components` and `VisualEditor/elements` must not import `@/features/presentation` barrels. Those pull member Puck config and control registration and can circularly leave palette components undefined. Import concrete modules.

## Forms, pages, and shell

- App `Form` is uncontrolled Inertia `Form` coordinated through `FormFieldContext`. Domain forms pass `initialData={{ model: record }}` and named inputs; do not field-pick or rebuild the payload. Inputs must forward `name` to a real control. Extra React state is only for UI that is not a submitted control; merge it in `transform`.
- Server validation failures `redirect_to` with `inertia: { errors: ... }`, not a 422 render.
- `Page` `title` is the browser tab; `heading` is the App shell header. Neither renders in the page body. `heading={null}` clears the shell header. `/circles` uses `hideNavMenu` because the user has not chosen a circle yet.
- In-app navigation uses Inertia (`Link`, `NavLink`, `Menu.Link`, `ButtonLink`). Plain anchors are for external URLs or internal `target="_blank"`.
- With Mantine headroom, a collapsed header can zero `--app-shell-header-offset` and shrink the page. The shell pins that offset to the header height while the bar is translated off-screen.

## Serializers and loading

- Computed serializer attributes must use the `attribute` block form; a bare `def` on the serializer is ignored.
- `Theme#orgs` and `Presentation#orgs` select join-table `ask_cents` / `ask_currency`. Do not `includes(:orgs)` or `preload(:orgs)` on those associations (including `includes_associated`): Rails' separate preload omits the join and raises `PG::UndefinedTable`. Lazy-load instead.
- `disable_menu_rendering` skips menu payloads on public Inertia responses.

## Frontend and tooling gotchas

- Import lodash-compatible helpers from `es-toolkit/compat`. Nested ternaries are forbidden.
- Do not nest `:global(.mantine-*)` under a Linaria class (it emits unscoped and leaks). Use `& .mantine-*` or Mantine `classNames`. Surface/hover colors must use `vars.lightSelector` / `vars.darkSelector` (or Mantine CSS variables), not a single light gray.
- XState `setup()` only accepts context/event types via `{} as T`. That is the allowed exception to the no-cast rule. Named actions fail if you write `setup<Context, Event>()` instead.
- Frontend tests assert user-facing behavior, not layout or ARIA shape. Inertia request specs assert `be_successful` unless lazy props would hide a serialization failure.
- Under jsdom, Mantine DataTable markup is often incomplete; do not assert the full grid DOM.
- Vitest must not `mergeConfig` the Rails `vite.config.ts`. That leaves file watchers open after `vitest run`.
- Node 25+ experimental global `localStorage` breaks jsdom Storage. Unit Vitest passes `--no-webstorage`.
- TypeScript 7 has no stable programmatic API; `typescript` stays aliased to TypeScript 6 for eslint, with `@typescript/native` for `tsc`.
- ESLint 10: `eslint-plugin-import` needs `@eslint/compat` `fixupConfigRules`, scoped to JS/TS files. Global ignores belong in a top-level `{ ignores }` object (generated serializers and coverage).
- Vitest mocks of `@inertiajs/react` must provide `useFormContext` or `Form` tests throw.
- Validation copy stays in Rails YAML and is excluded from the frontend i18n export. Do not hardcode English in `errors.add`.
