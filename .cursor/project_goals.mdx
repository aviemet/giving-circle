## Interactions: form and response config as one authoring surface

**Status:** Shipped (Puck member screens).

Member-facing layout lives in `member_ui` (Puck JSON). `Interactions::MemberUiCompiler` compiles placed interaction input components into `config.fields`, `config.outputs`, `config.settings`, and `config.orchestration` on save, so the member screen and response schema stay aligned.

Admin edits member screens in the Visual Editor (`.../member_ui/edit` on templates and presentation interactions). Runtime renders via `MemberInteractForm` with catalog-bound input components under `components/VisualEditor/components/interaction/`.

Remaining polish (not blocking the goal): richer orchestration admin UI, multi-select funding basis in Puck root fields, and stricter client-side submit gating tied to partial-submit checkboxes.
